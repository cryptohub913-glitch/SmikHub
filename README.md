# SmikHub

Telegram-бот и backend API платформы SmikHub.

## Что реализовано

**🤖 Продать ОП** — владелец подключает своего Telegram-бота по токену и управляет его
настройками (тематики спонсоров, минимальная цена, лимит спонсоров, интеграции
Subgram/Flyer/Tgrass/PiarFlow, приоритет площадок, токен интеграции, пауза/удаление).
Flyer/Tgrass/PiarFlow подключены по-настоящему:
- backend реально ходит в их API за живыми спонсорскими задачами (`GET /api/v1/bot/sponsors`)
  и сверяет выполнение (`POST /api/v1/bot/sponsors/check`);
- если подключён Tgrass — реальный пол/возраст/страна известных ему пользователей
  участвуют в таргетинге собственного инвентаря `botohub`;
- PiarFlow можно подключить в одно касание («🔗 Подключить автоматически» — без ручной
  вставки ключа), с ручным вводом как запасным вариантом;
- «📈 Статистика» показывает реальные цифры (баланс, подписки/отписки, доход) из
  подключённых сетей вместо заглушки.

Subgram, как и раньше, — только хранение токена (по нему не было документации API).
Подробности и честные ограничения — в
[docs/integrations.md](docs/integrations.md#4-flyer--tgrass--piarflow-реальная-выдача-спонсоров-и-subgram).

**Для владельцев ботов, которые хотят подключить свой бот к SmikHub и реально показывать
спонсоров** — пошаговая инструкция по `/api/v1/bot/sponsors` и `/api/v1/bot/sponsors/check`
(с примерами запросов/ответов и кодом) в
[docs/api-integration.md](docs/api-integration.md).

**🛍 Купить ОП** — рекламодатель создаёт заказ (тип трафика, назначение — канал/чат, бот
или внешний ресурс), настраивает цену, таргетинг (тематики, пол, возраст, TG Premium,
языки, страны), лимиты пользователей в день/всего. Оплата — с внутреннего баланса
(«Кабинет» → «Пополнить»).

**🎴 Кабинет** — баланс, реальное пополнение и вывод через Send Crypto Pay API
(help.send.tg): `createInvoice`/вебхук для пополнений, заявка + одобрение админом → `transfer`
для вывода (вывод сделан именно так, а не мгновенным `transfer` с кнопки пользователя,
потому что `transfer` необратим — заявка даёт шанс отловить баг/абьюз до реальной отправки
денег).

**🛠 Админ-панель** (`/admin`, только для Telegram ID из `ADMIN_USER_IDS`, проверяется на
уровне роутера — не только команды, но и всех колбэков) — заявки на вывод (одобрить/
отклонить), статистика платформы (в т.ч. по каждому боту и по конкретному пользователю по
ID), управление пользователями (бан/разбан, ручная коррекция баланса), вкл/выкл разделов
«Продать ОП»/«Купить ОП», статус интеграций Send Pay/check-бота, а также **«💰 Цены и
лимиты»** и **«🏷 Тематики»**:
- Цены и лимиты — мин. суммы пополнения/вывода, границы сетки «Мин. цена» и значение по
  умолчанию для новых ботов в «Продать ОП», границы сетки «Макс. спонсоров» и дефолт для
  новых ботов, границы сетки цены заказа в «Купить ОП». Всё это раньше было зашито в код
  константами — теперь редактируется из чата и реально влияет на сетки, которые видят
  пользователи.
- Тематики — полноценный CRUD списка тематик спонсоров (добавить/переименовать/удалить),
  а не фиксированный список из кода; удаление тематики каскадно убирает её из фильтров
  ботов и заказов, где она была выбрана.

Backend API отдаёт **конфигурацию** подключённого бота по токену интеграции, принимает
вебхук Send Pay, и выдаёт реальных спонсоров сразу из двух источников: внешних сетей
(Flyer/Tgrass/PiarFlow) и **собственного инвентаря платформы** — заказов «Купить ОП» под
площадкой `botohub`, смешанных с внешними по приоритету бота. В инвентарь `botohub`
попадают только заказы с назначением «Канал/чат» и подтверждённым check-ботом (для
«Бот»/«Ресурс» нет способа подтвердить выполнение), с реальным учётом `is_premium` и языка
пользователя из таргетинга заказа. Пол/возраст/страна заказа и «Распределение в течение
дня» — пока не подключены к реальной логике (нет источника данных о пользователе и движка
распределения показов соответственно). Подробности — в
[docs/api-integration.md](docs/api-integration.md).

**📜 Лог начислений** (кнопка в панели заказа «Купить ОП») — детальная лента по каждому
подтверждённому вступлению: сумма, ссылка, ID/юзернейм, метка `resource_unlock`, свой
скоринг «качество/некач» (эвристика: вышел из чата быстрее часа после вступления —
считаем накруткой). Это честный аналог похожего лога у конкурентов на данных, которые у
нас реально есть — без пола/возраста и DC/региона (не даёт Bot API) и без стороннего
сервиса вроде Telelog (нет доступа — не стал изображать интеграцию, которой нет).

### Проверка вступлений — check-бот

Для заказов с назначением «Канал/чат» реальные вступления/отписки проверяет отдельный
Telegram-бот (`smikhub/checkbot`), которого рекламодатель добавляет в администраторы
своего канала/чата. Только тогда включается реальная статистика и списание с баланса за
подтверждённые вступления.

**Ограничения (честно, чтобы не выдавать желаемое за действительное):**
- Поддерживаются только **публичные** ссылки на канал/чат (`t.me/username`) — у Bot API
  нет способа безопасно резолвить приватную инвайт-ссылку без риска перепутать чужие чаты.
- Для назначений «Бот» и «Ресурс (без проверки)» реальной проверки трафика нет и не может
  быть (нет доступа к чужому боту; «без проверки» — так и заявлено в ТЗ) — статистика для
  них остаётся нулевой, без имитации данных.
- «📍 Места показа» в панели заказа — заглушка «в разработке» (экран не был описан в
  присланном ТЗ).
- У меня нет реального токена Send API и публичного HTTPS для вебхука, поэтому живой платёж
  и живую выплату я проверить не мог — код написан строго по документации
  (`createInvoice`/`getInvoices`/`transfer`, подпись `HMAC-SHA256(sha256(token), body)`),
  но финальную проверку с реальными ключами нужно сделать самостоятельно. Точный базовый
  URL Send API (`SEND_API_BASE_URL`) стоит сверить с личным кабинетом приложения — в
  доступной мне статье он не был явно указан, сейчас это значение по аналогии с
  `pay.crypt.bot`.
- Хранение самих секретных токенов (`BOT_TOKEN`/`CHECK_BOT_TOKEN`/`SEND_API_TOKEN`) остаётся
  в `.env`, а не в БД через чат-админку — админ-панель показывает только их статус
  («настроен»/«нет»), это осознанное решение по безопасности.

## Стек

Python 3.11+, aiogram 3, SQLAlchemy 2 (async) + SQLite, FastAPI, cryptography (Fernet),
aiohttp (клиент Send Pay).

## Установка

```bash
python -m venv .venv
.venv/Scripts/activate        # Windows
# source .venv/bin/activate   # Linux/macOS

pip install -e ".[dev]"
cp .env.example .env
```

В `.env` укажите:
- `BOT_TOKEN` — токен основного бота SmikHub (от @BotFather)
- `CHECK_BOT_TOKEN` — токен отдельного check-бота (второй бот от @BotFather); опционален,
  но без него заказы на «Канал/чат» не получат реальной проверки и биллинга
- `FERNET_KEY` — сгенерировать: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
- `ADMIN_USER_IDS` — свой Telegram ID (и коллег), через запятую, для доступа к `/admin`
- `SEND_API_TOKEN`, `SEND_API_BASE_URL` — данные приложения Send Crypto Pay (создаётся у
  @CryptoBot/Send); без них «Кабинет» показывает баланс, но пополнение/вывод отключены с
  понятным сообщением, а не падают с ошибкой

Вебхук для Send Pay нужно один раз указать в настройках самого приложения Send —
`https://<ваш-домен>/webhooks/send-pay`.

**Подробный пошаговый гайд по подключению Send Pay и check-бота (где взять токены, как
настроить вебхук, что именно я не смог проверить сам) — в [docs/integrations.md](docs/integrations.md).**

## Запуск

Telegram-бот SmikHub:

```bash
python -m smikhub.bot.main
```

Check-бот (проверка вступлений для «Купить ОП»):

```bash
python -m smikhub.checkbot.main
```

Backend API (плюс вебхук Send Pay):

```bash
uvicorn smikhub.api.main:app --reload
```

Или все три сервиса разом через Docker:

```bash
docker compose up --build
```
