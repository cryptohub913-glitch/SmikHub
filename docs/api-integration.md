# Интеграция вашего бота со SmikHub — полная инструкция

Эта инструкция — для владельца бота, который подключил его в разделе **«🤖 Продать ОП»** и
получил **токен интеграции**. Она объясняет, что именно нужно сделать в коде **своего**
бота, чтобы он начал реально показывать спонсоров и получать за это деньги.

---

## 1. Идея в двух словах

SmikHub сам не работает как ваш бот — он работает как **биржа спонсоров у вас за спиной**.
Источников спонсоров два вида: внешние рекламные сети, которые вы сами подключаете
(Flyer / Tgrass / PiarFlow), и **собственный инвентарь платформы** — реальные заказы
рекламодателей из раздела «🛍 Купить ОП» (площадка `botohub`), которые SmikHub подмешивает
в выдачу автоматически, без каких-либо действий с вашей стороны. SmikHub отдаёт вам через
свой API уже готовый, смешанный и отфильтрованный список: "покажи вот эти N спонсоров
этому пользователю". Дальше — три шага, которые должен делать код именно **вашего** бота:

1. Когда пользователю нужно показать спонсоров (например, чтобы открыть доступ к контенту)
   — ваш бот спрашивает у SmikHub: **"что показать этому юзеру?"**
2. Ваш бот сам рисует эти спонсорские задания пользователю (кнопки "Подписаться на канал"
   и т.п.) и кнопку "✅ Я подписался / Проверить".
3. Когда пользователь жмёт "Проверить" — ваш бот спрашивает у SmikHub: **"он правда всё
   выполнил?"** Если да — открываете доступ.

SmikHub не проверяет подписки сам за вас "по умолчанию из коробки" — эту проверку по факту
делают сети (Flyer/Tgrass/PiarFlow), а SmikHub просто прокси-запросом ходит к ним вместо
того, чтобы вам самим интегрироваться с каждой сетью отдельно.

---

## 2. Где взять токен

«🤖 Продать ОП» → выберите бота → **«🔑 Токен интеграции»**. Это долгая случайная строка,
например `r2UdFJZ4aTp9GdJahcKsPjiZuWRW7pQDZfhVzTl6n1c` — держите её в секрете, как пароль.
Это единственный способ авторизации в API, привязанный именно к вашему боту.

---

## 3. Базовый адрес и авторизация

```
Base URL: https://<адрес, на котором развёрнут smikhub.api.main:app>
```

Точный адрес зависит от того, где именно поднят backend API SmikHub (см. `## Запуск` в
README платформы — `uvicorn smikhub.api.main:app`). Уточните его у администратора
платформы, если не разворачивали сами.

Каждый запрос должен нести заголовок:

```
Auth: <ваш токен интеграции>
```

Если токен неверный или бот на паузе (кнопка «⏸️ Приостановить» в панели) — любой запрос
вернёт:

```json
HTTP 401
{"detail": "Invalid or inactive integration token"}
```

## 4. `GET /api/v1/bot/config` — настройки вашего бота

Просто отдаёт то, что вы сами настроили в панели «Продать ОП» — на случай, если вашему коду
нужно это знать (например, показать пользователю, включён ли бот).

**Запрос:**

```
GET /api/v1/bot/config
Auth: <токен>
```

**Ответ:**

```json
{
  "bot_username": "fenixtwobot",
  "is_active": true,
  "category_mode": "all_except_own",
  "min_price": 0.5,
  "max_sponsors": 3,
  "disabled_categories": ["casino", "adult"],
  "provider_priority": ["botohub", "flyer", "tgrass"]
}
```

| Поле | Тип | Что значит |
|---|---|---|
| `bot_username` | строка | username вашего бота в Telegram |
| `is_active` | bool | бот включён (не на паузе) |
| `category_mode` | строка | `all_except_own` или `only_own` — режим тематик (пока не влияет на выдачу спонсоров, см. ограничения ниже) |
| `min_price` | число | ваш порог "Мин. цена" — этим же порогом уже отфильтрован `/sponsors`, вам вручную фильтровать не нужно |
| `max_sponsors` | целое | сколько спонсоров максимум вы получите за раз в `/sponsors` |
| `disabled_categories` | список строк | коды отключённых тематик (см. ограничение про тематики ниже) |
| `provider_priority` | список строк | в каком порядке подключены площадки: `botohub` (свой инвентарь платформы — реальные заказы «Купить ОП»), `subgram`, `flyer`, `tgrass`, `piarflow` |

## 5. `GET /api/v1/bot/sponsors` — получить, что показать пользователю

Это основной метод. Дёргаете его каждый раз, когда нужно показать пользователю спонсоров
(например, при `/start` или когда закончился прошлый набор заданий).

**Запрос:**

```
GET /api/v1/bot/sponsors?user_id=123456789&chat_id=123456789&is_premium=false&lang=ru
Auth: <токен>
```

| Параметр | Обязателен | Тип | Что значит |
|---|---|---|---|
| `user_id` | да | int | Telegram ID пользователя, которому показываем спонсоров |
| `chat_id` | нет | int | ID чата с пользователем; если не передать — берётся равным `user_id` (это верно для обычной личной переписки с ботом) |
| `is_premium` | нет | bool | есть ли у пользователя Telegram Premium — некоторые сети это учитывают |
| `lang` | нет | строка | код языка интерфейса пользователя (`message.from_user.language_code`), по умолчанию `"ru"` |

**Ответ** — список от 0 до `max_sponsors` штук:

```json
[
  {
    "provider": "botohub",
    "task_id": "42",
    "title": "https://t.me/advertiser_channel",
    "link": "https://t.me/advertiser_channel",
    "price": "3.00",
    "task_type": "subscriptions"
  },
  {
    "provider": "flyer",
    "task_id": "AbCdEf123signature",
    "title": "Крутой канал",
    "link": "https://t.me/some_channel",
    "price": "1.50",
    "task_type": "subscribe channel"
  },
  {
    "provider": "tgrass",
    "task_id": "off-9182",
    "title": "Ещё один канал",
    "link": "https://t.me/another_channel",
    "price": null,
    "task_type": "channel"
  }
]
```

| Поле | Что значит |
|---|---|
| `provider` | откуда эта задача: `botohub` (свой инвентарь платформы, реальный заказ из «Купить ОП») либо сеть `flyer` / `tgrass` / `piarflow` — нужно **сохранить у себя**, оно понадобится при проверке (шаг 6) |
| `task_id` | идентификатор задачи (для `botohub` — это ID заказа в SmikHub, для сетей — их собственный signature/offer_id/link) — тоже нужно сохранить, тоже понадобится при проверке |
| `title` | название — что показать пользователю текстом. Для `botohub` мы пока не храним отдельное название канала — здесь просто ссылка, как есть |
| `link` | на что должна вести кнопка "Подписаться"/"Перейти" |
| `price` | сколько вам заплатят за выполнение (в валюте платформы). **Может быть `null`** — это не баг, это значит, что сеть (сейчас так у Tgrass) не сообщает цену конкретной задачи через API. У `botohub` цена есть всегда |
| `task_type` | для `botohub` — тип трафика заказа (`subscriptions`/`views`); для внешних сетей — тип задания как есть у сети-источника (`"subscribe channel"`, `"channel"`, и т.п.), единого стандарта между сетями нет |

**Про `botohub` отдельно:** это реальные заказы из «Купить ОП», а не демо-данные. В выдачу
попадают только заказы с назначением «Канал/чат», где рекламодатель уже подтвердил
check-бота администратором (иначе мы физически не можем проверить выполнение). Заказы
«Бот»/«Ресурс» сюда не попадают — по той же причине, по которой в них не работает
статистика (см. README). Из реального таргетинга заказа на `botohub`-задачи всегда влияют
`is_premium` и `lang`, которые вы и так передаёте в этот запрос — если рекламодатель
включил «Только Premium» или исключил ваш язык интерфейса, такой заказ вам просто не
придёт. **Пол/возраст/страна заказа** тоже могут повлиять, но только если у **вашего**
бота подключён Tgrass и он уже знает конкретного пользователя (его `/subscriber` отдаёт
эти поля) — тогда мы честно фильтруем по ним; если Tgrass не подключён или не знает
пользователя, эти фильтры заказа просто не проверяются (см. раздел 10).

**Что уже сделано за вас** (не нужно повторять в своём коде):
- Список уже отфильтрован по вашему `min_price` из панели бота.
- Список уже не длиннее вашего `max_sponsors`.
- Порядок задач уже соответствует вашему приоритету площадок («🔀 Приоритет» в панели).
- Если какая-то сеть временно недоступна — она просто пропускается, запрос всё равно
  вернёт то, что удалось получить от остальных (не упадёт целиком из-за одной сети).

**Если список пустой `[]`** — это нормальная ситуация, не ошибка. Причины: у вас пока не
подключена ни одна сеть, либо все доступные задачи оказались дешевле вашего `min_price`,
либо сеть(и) прямо сейчас недоступны.

## 6. `POST /api/v1/bot/sponsors/check` — проверить, выполнил ли пользователь

Вызывайте, когда пользователь нажал у вас в боте что-то вроде "✅ Я подписался" / "Проверить".

**Запрос:**

```
POST /api/v1/bot/sponsors/check
Auth: <токен>
Content-Type: application/json

{
  "user_id": 123456789,
  "tasks": [
    {"provider": "flyer", "task_id": "AbCdEf123signature"},
    {"provider": "tgrass", "task_id": "off-9182"}
  ]
}
```

В `tasks` передайте ровно те `provider`+`task_id`, которые вы получили и показали
пользователю в шаге 5 (можно все сразу, можно только те, что ещё не подтверждены).

**Ответ:**

```json
[
  {"provider": "flyer", "task_id": "AbCdEf123signature", "status": "completed"},
  {"provider": "tgrass", "task_id": "off-9182", "status": "not_completed"}
]
```

Возможные значения `status`:

| Статус | Что значит | Что делать |
|---|---|---|
| `completed` | пользователь выполнил условие (подписался и т.п.) | засчитать, открыть доступ |
| `pending` | сеть ещё не подтвердила — обычно значит "подождите немного" | попросить пользователя подождать/нажать ещё раз попозже |
| `not_completed` | пользователь точно не выполнил (отписался/не подписывался) | не открывать доступ, предложить попробовать снова |
| `unknown` | сеть не смогла ответить, либо задача от сети, которая у вас не подключена/недоступна | на практике лучше трактовать как "ещё не подтверждено", не как жёсткий отказ |

Для `provider: "botohub"` статус — это не поход во внешний API, а прямая проверка по
нашей же базе: `completed`, если check-бот платформы зафиксировал реальное вступление
этого `user_id` в целевой чат заказа и пользователь из него не выходил; иначе
`not_completed`. `pending`/`unknown` для `botohub` не возвращаются — либо есть
подтверждённое вступление, либо нет.

**Открывать доступ имеет смысл только тогда, когда `status == "completed"` для ВСЕХ
заданий**, которые вы обязали пользователя выполнить.

## 7. Полный сценарий целиком (псевдокод)

```python
# 1. Пользователь запустил бота — нужно показать спонсоров
sponsors = GET /api/v1/bot/sponsors?user_id={user.id}&lang={user.language_code}

if not sponsors:
    # спонсоров нет — открываем доступ сразу, показывать нечего
    unlock_access(user)
else:
    # запоминаем, что именно показали этому юзеру (в своей БД/памяти)
    save_shown_tasks(user.id, sponsors)  # [(provider, task_id), ...]
    show_buttons(sponsors)  # кнопка-ссылка на каждый task.link + кнопка "✅ Проверить"

# 2. Пользователь нажал "✅ Проверить"
shown = load_shown_tasks(user.id)
results = POST /api/v1/bot/sponsors/check
    {"user_id": user.id, "tasks": [{"provider": p, "task_id": t} for p, t in shown]}

if all(r["status"] == "completed" for r in results):
    unlock_access(user)
else:
    remaining = [r for r in results if r["status"] != "completed"]
    tell_user_to_finish(remaining)
```

## 8. Пример кода на Python (aiohttp)

```python
import aiohttp

BASE_URL = "https://ВАШ-ДОМЕН-API"
AUTH_TOKEN = "r2UdFJZ4aTp9GdJahcKsPjiZuWRW7pQDZfhVzTl6n1c"


async def get_sponsors(user_id: int, lang: str = "ru") -> list[dict]:
    async with aiohttp.ClientSession() as session:
        async with session.get(
            f"{BASE_URL}/api/v1/bot/sponsors",
            params={"user_id": user_id, "lang": lang},
            headers={"Auth": AUTH_TOKEN},
        ) as response:
            response.raise_for_status()
            return await response.json()


async def check_sponsors(user_id: int, tasks: list[dict]) -> list[dict]:
    async with aiohttp.ClientSession() as session:
        async with session.post(
            f"{BASE_URL}/api/v1/bot/sponsors/check",
            json={"user_id": user_id, "tasks": tasks},
            headers={"Auth": AUTH_TOKEN},
        ) as response:
            response.raise_for_status()
            return await response.json()
```

## 9. Обработка ошибок и практические советы

- **`401 Unauthorized`** — токен неверный или бот на паузе. Проверьте, что скопировали
  токен без пробелов и что бот включён («⏸️ Приостановить» в панели — если там написано
  «▶️ Запустить», значит бот сейчас выключен).
- **Пустой список от `/sponsors`** — не ошибка, см. раздел 5.
- Не нужно дёргать `/sponsors` слишком часто "на всякий случай" — берите свежий список
  каждый раз, когда реально нужно показать спонсоров новому юзеру или когда прошлый набор
  исчерпан/устарел, а не по таймеру.
- Сохраняйте у себя, какие именно `provider`+`task_id` вы показали конкретному
  пользователю — без этого нечего будет передать в `/sponsors/check`.

## 10. Честные ограничения (чтобы не было сюрпризов)

- **Фильтр тематик бота не действует ни на внешних спонсоров, ни на `botohub`.** Ни одна из
  сетей не сообщает тематику/категорию задачи через API, а у наших собственных заказов и
  ботов нет единого поля "какая это тематика" для сопоставления (это структурная
  особенность исходной модели данных, не забытая мелочь). `disabled_categories` из
  `/config` сейчас ни на что в `/sponsors` не влияет — ни для внешних сетей, ни для
  `botohub`.
- **У Tgrass нет цены задачи** — `price` для его заданий всегда `null`, фильтр «Мин. цена»
  к ним не применяется вообще (они всегда проходят). У `botohub` цена есть всегда.
- **`botohub` всегда учитывает `is_premium` и `lang`** из реального таргетинга заказа.
  **Пол/возраст/страна заказа учитываются только если у вас подключён Tgrass** и он уже
  знает конкретного пользователя (его `/subscriber` отдаёт эти поля) — тогда мы честно их
  проверяем; без Tgrass или для незнакомого ему пользователя эти фильтры заказа не
  применяются вообще, ни в плюс, ни в минус. «Распределение показов в течение дня» у
  заказа тоже пока не влияет на выдачу — это просто сохранённый флаг без движка
  распределения по времени.
- **`botohub` работает только для заказов с назначением «Канал/чат»**, где рекламодатель
  подтвердил check-бота в администраторах. Заказы «Бот»/«Ресурс» никогда не появятся в
  `/sponsors` — по ним нет способа подтвердить выполнение.
- Из возможностей самих сетей через API SmikHub наружу выведены получение задач, проверка
  выполнения, а также (с недавних пор) статистика бота и профиль подписчика у
  Tgrass/PiarFlow, статус ключа у Flyer. `reset_offers` у Tgrass и `get_completed_tasks` у
  Flyer по-прежнему не выведены — для основного сценария "показать → проверить" они не
  нужны.

---

*Если что-то в этой инструкции не сходится с реальным поведением API — это надёжнее, чем
любое её текстовое описание, потому что код никогда не устаревает молча: смотрите
`smikhub/api/routers/sponsors.py` и `smikhub/api/routers/config.py` в репозитории
платформы.*
